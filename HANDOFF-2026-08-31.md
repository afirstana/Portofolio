## 01. EXECUTIVE SYSTEM OVERVIEW & ARCHITECTURE

### 1.1 Core Mission & Engineering Philosophy
Abimael.Data is a high-performance, spec-driven developer and data engineering portfolio built with **Next.js 15 (App Router)**, **React 19**, **TypeScript 5 (Strict Mode)**, **Tailwind CSS 4**, and **Vitest**.

Unlike generic web portfolios, this system enforces:
- **Ultra-Minimalist Monospace Aesthetics**: Razor-sharp typography (`Courier New` and clean system sans), high-contrast monochrome obsidian panels (`#050506`, `#0b0b0e`), and deliberate accent highlights (`#ff4d1c` dark / `#0284c7` light).
- **Zero AI-Slop Design Policy**: No rounded cartoonish cards, no bloated emojis in menus, no oversized gradient blobs, and no unformatted markdown dumps.
- **Empirical Rigor**: All analytical claims are backed by structured tables, mathematical equations ($KaTeX$), interactive web simulators, and verifiable production metrics.
- **Extreme Client-Side Reliability**: 100% test pass rate across 232 test suites, featuring sub-pixel physics stress testing, adversarial Delta Time ($dt$) jitter resilience, and non-intrusive interactive canvas butterfly kinematics.

## 06. STANDARD OPERATING PROCEDURES (SOP)

### SOP 01: Authoring a New Project Case Study
1. Create a new markdown file in `content/projects/<kebab-case-slug>.md`.
2. Provide required YAML frontmatter:
   ```yaml
   title: "Project Title"
   subtitle: "Clear, descriptive technical subtitle"
   slug: "kebab-case-slug"
   date: "2026-08-31"
   tags: ["Tag1", "Tag2"]
   metrics:
     - label: "Key Metric 1"
       value: "99.4%"
     - label: "Key Metric 2"
       value: "+42.5% GMV"
   ```
3. Start the body with an executive summary alert:
   ```markdown
   > [!NOTE]
   > **Executive Summary**:
   > - **Problem**: Describe core operational inefficiency.
   > - **Technical Solution**: Describe architectural and algorithmic approach.
   > - **Impact**: Quantified production business results.
   ```
4. Use numbered headings (`## 01. ...`, `## 02. ...`), structured comparison tables, and properly escaped currency symbols (`\$500k`).
5. Run test verification: `npm test`.

---

### SOP 02: Adding a New Certification or Academy Track
1. Create a new markdown file in `content/learning/<kebab-case-slug>.md`.
2. Provide complete YAML frontmatter:
   ```yaml
   title: "Certification / Track Name"
   subtitle: "Technical competencies and scope"
   slug: "kebab-case-slug"
   provider: "Certification Authority / Organization"
   status: "Active (In Progress) / Verified / Completed"
   progressPct: 100
   progressFraction: "X/Y Requirements"
   startDate: "Month Year"
   endDate: "Month Year"
   category: "Data Analytics / Cloud & AI / Software Engineering"
   badge: "CREDENTIAL BADGE"
   tags: ["Tag1", "Tag2"]
   modules:
     - name: "Module 1: Title"
       url: "https://credential-link"
       status: "Completed / Active"
       level: "Foundational / Intermediate / Applied / Exam"
       summary: "Technical topics covered."
   thesis: "Core technical objective of the certification."
   ```
3. Write the markdown syllabus and examination pillars under numbered headings (`## 01. ...`, `## 02. ...`).
4. The new certification will automatically appear in the `/learning/` Compact Data Table and generate its static detail page at `/learning/<kebab-case-slug>/`.
